# Completion and derived output

Validate every manifest chunk against a nonempty note and source evidence. Counts alone are insufficient: compare exact IDs in order, source ranges and note paths. Resolve failed chunks. Write a scope-labelled synthesis, then set schema 2.0 status=completed, next_chunk=null, synthesis=<relative path>. Run validate_reading_project.py; a zero exit code only proves structural checks. Inspect the actual note quality before announcing completion.

For partial-book contracts, label every synthesis with the selected range, never the entire book. If contracted, derive a one-page outline from verified notes: thesis, chapter map, key method/argument, a few verified short quotations with source locations, and a reading guide. Do not re-read unnecessarily, invent quotes or reproduce long passages.

Local output is the default. Cloud documents or messages are separate optional actions requiring explicit authorization for the material, service, recipient and visibility. Inspect current tool interfaces; do not assume a particular CLI, bot identity or organization-wide visibility. Verify permissions do not exceed the approved audience before sharing. Report prepared/uploaded/sent states separately and keep identifiers only in the private reading project. If the provider is unavailable, deliver the local document and explain the limitation.
