# 国内直连与跨境分流（v0.5.1）

此可选策略面向人在中国大陆、使用海外 CDN 节点的场景。默认无自有域名的 Hysteria2 路线和原 CDN 渲染接口保持兼容。不要把此策略直接应用到境外访问国内的回国线路。

## 配置与交付

在原有 `cdn.py --values` JSON 中增加以下字段；路径必须是部署环境的绝对路径，SHA-256 必须对应已审阅的真实文件：

```json
{
  "routing_profile": "cn-direct",
  "routing_data": {
    "domain": {"path": "/opt/tunnel/rules/cn-domain.list", "sha256": "REPLACE_WITH_REVIEWED_SHA256"},
    "ip": {"path": "/opt/tunnel/rules/cn-ip.list", "sha256": "REPLACE_WITH_REVIEWED_SHA256"}
  },
  "direct_processes": []
}
```

这只是附加字段示例，不能单独作为完整 values 使用。Windows 使用相应绝对路径。domain 文件每行一个域名或 `+.example.cn` 后缀，ip 文件每行一个规范 CIDR；允许空行和以 `#` 开头的注释。每份不超过5MB、20万有效行；缺少或错误哈希拒绝渲染，不能退回全代理冒充成功。

规则数据由操作者单独获取、审阅和固定版本，不随本 MIT 包分发。可评估 [MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat)，使用前核对其来源、格式和 GPL-3.0 许可义务。不要将下载内容默认为本项目 MIT 代码；再分发生成配置时也需评估其中嵌入数据的许可。

发布端 policy.values 和接入端 monitor values 都需配置此策略，数据内容及 SHA 一致，路径可因机器不同而不同。先比较两端渲染的完整 YAML 哈希，再使用原有受限发布流程。expected_new_sha256 校验阻止发布端漂移；失败保留旧配置。规则数据内嵌 YAML，客户端首次启动无需再下载外部规则库。

## 路由逻辑

- 经实机确认后才加入 direct_processes；默认不提供进程级绕过。该规则意味着这个进程的全部连接直连，应谨慎限定。
- 局域网直连；显式海外服务规则先于国内数据集，海外 TCP 走 SILICON，海外 UDP 拒绝。
- 国内域名直连，最后才拒绝剩余 UDP、将剩余 TCP 交给 SILICON。v0.5.1 不再自动启用国内 IP 数据集直连；旧 ip 快照输入仍校验并内嵌以保持接口兼容，但不参与直连匹配。
- 国内和 DIRECT 查询用国内 DoH 直连；海外默认 DNS 走隧道；节点自身 DNS 独立直连，避免启动循环。
- 节点认证、TLS 校验和服务器出口配置保持不变。没有通过关闭证书校验改善连接。

国内 UDP 不再被全局拒绝，不代表当前 VMess/WS 服务支持海外 UDP。

## 客户端更新

Windows Clash Verge 与 Android Clash Meta 使用原私密订阅执行更新，再激活配置并保持规则模式。保留用户通过客户端“编辑规则”添加的扩展，核查实际运行规则和连接命中；不要假设看见配置文本就代表生效。直接修改订阅 YAML 的内容可能在更新时被覆盖。

私密订阅是固定下载地址，返回的仍是 YAML。以前手动导入的文件是旧快照，不会跟着订阅更新。日常用订阅；从已发布版本保存带日期与哈希的离线快照作应急备用，避免重新激活旧文件。离线快照不会自动追踪入口变化，含凭据，应与订阅链接同样保护。

规则更新后，已有长连接可能沿用原链路；在用户方便时重新连接远控或应用，再验收。不要主动断开正在使用的远控会话。iOS 订阅格式及连通性需单独验证，不把 Windows/Android 成功扩写为 Shadowrocket 已通过。

## 巡检与性能

巡检在接入端运行独立的官方 Mihomo 文件，并校验固定 SHA-256；不要引用会被 Clash Verge 自动升级替换的安装目录文件。这个独立内核不替换用户上网的内核。升级巡检内核需重新核验来源、哈希、隔离配置和探针后更新设置，不能删除哈希校验。

监测 settings 可加入 `"performance": true`。成功的线路检查后记录两次小请求与一次5MB下载样本；这些测试会消耗流量。health 表示连通，quality 表示此次有限样本的结果，不能代表全天速度。速度样本不参与入口替换，避免因一次快慢频繁切换。

三种周期保持分离：客户端回退检查60秒、订阅建议刷新6小时、接入端巡检48小时。异常入口仅在5分钟后复核一次；证据不足或没有足够替代入口时保留旧配置。计划任务注册成功、手动触发成功和自然触发成功须分别留证。

## 经验与验收边界

现场曾出现国内网站、语音和远控都慢：实际运行规则将 TCP 全部送往海外，并在国内匹配前拒绝所有 UDP。修复国内路由、DNS及 UDP 顺序后，用户反馈 Windows/Android 国内网页、微信、百度语音、短时 YouTube 播放与远控响应显著改善；订阅更新与自定义规则保留也经用户确认。

核心经验是先检查实际走哪条路，再讨论增加带宽。磁盘扩容不改善跨境延迟；更高标称带宽不消除绕行、丢包或 DNS 阻塞。TUN 负责接管流量，分流规则决定接管后送哪里。

旧诊断教训：第三方订阅测速成功不证明自建节点成功；服务器服务 active 不证明用户线路畅通；同一家 CDN 的多个入口也不是独立备用网络。分别验证 DNS、TCP/TLS、隧道认证、目标响应和真实应用。源站防护、证书验证和私密订阅边界应保留。

上述是一次现场验收，不保证所有运营商和时段稳定。30分钟视频、重复语音、晚高峰、自然巡检及 iOS 应分别验收，不能由短时请求或单元测试代替。

## Google Play 页面正常、下载等待

一例已验收故障中，Info日志明确显示 services.googleapis.cn 命中国内域名直连，后续 xn--ngstr-lra8j.com 下载节点却走海外代理。修复这两个域名后缀的代理优先级与显式代理 DNS，并取消旧等待任务重新安装后，用户确认原私密订阅下载成功。此结论限于该现场；未抓取 Google 服务端拒绝原因，不把入口或带宽假设写成事实。

保护规则必须同时保留在服务器发布器与接入端渲染器，入口更新时比较 expected_new_sha256；旧版发布器产生不同内容应拒绝发布。更新后逐字节回读订阅和离线快照，真实设备业务验收另行记录。

排查先记录 Info 级别实际连接，区分商店页面、服务 API、下载 CDN；Warning 日志可能遗漏关键成功连接。配置重载附近的默认 DIRECT 记录不能代表稳定运行规则。单次下载成功和仅配置解析通过都不足以证明根因；不同配置必须核实具体差异，最终用原订阅更新后真实下载验收。临时恢复全部代理会牺牲国内体验，不应直接作为正式分流方案。
