# 实战经验：症状、修复与证据边界

这些经验由维护者提供的原创 YouTube 云 IP 排障记录 v1.1（2026-09-06）整理。原案例记录了客户端 WARP-over-Hy2 最终通过普通视频、音乐 MV、直播三类测试。本包只保留可复用方法；原始 IP、主机名称、账号、私人文档路径与凭据不随包发布，也不要求读者访问私人知识库。

## 迭代经验如何进入本包

| 案例中的现象 | 经验与修复 | 本包落点 | 验证与限制 |
|---|---|---|---|
| Hy2 可连接，但部分视频无法播放 | 将入口传输与公网出口分开诊断；确认出口问题后评估客户端 WARP 链式 | [F03](troubleshooting.md)、[链式模板](../examples/client-hy2-warp.template.json) 的 dialer-proxy | 固定账号／应用／样本做对照，不将错误提示等同于 IP 被封 |
| 其他站点通，Google 系无网络 | 错误 DNS 答案可能让 WARP 连接错误地址；用隧道内可信解析，检查引导循环 | [F04](troubleshooting.md)、模板的 dns 与 WireGuard 远端解析 | DNS 路径取决于内核与应用；不是 WireGuard 协议永远要求本地解析 |
| 改 DNS 后页面可开，但仍出现异常流量 | 登录、视频、静态资源走不同出口可能导致会话不一致；统一相关域名出口 | [F05](troubleshooting.md)、模板 14 条 Google/YouTube 规则及 GOOGLE 组 | 原案例将出口分裂列为关键线索；不能推导出 Google 内部风控的唯一判据 |
| 小请求可用，大请求／视频不稳 | 双层封装可能放大分片丢包；逐项对照 MTU | [F06](troubleshooting.md)、WARP_MTU 参数 | 案例最终保留 1100；早期降低 MTU 并未单独解决全部问题，不能宣称已证明唯一根因 |
| UDP/443 测试未改变现象 | 规则顺序可能让拒绝规则根本没执行 | [F07](troubleshooting.md)、[链式说明](client-warp.md) | 测试规则须在会提前匹配的规则前；拒绝 UDP 不等于应用一定回退 TCP |
| 切换另一地区云主机仍失败 | 换地区本身不保证改善出口质量 | [F03](troubleshooting.md)、[备用路线](optional-routes.md) | 两个节点的失败不足以证明所有云 IP 被全面屏蔽 |
| 风控后来再次出现 | 重新确认真实出口、规则和当前样本，再决定有限重试或其他出口 | [F08](troubleshooting.md)、[链式回退](client-warp.md) | 不自动循环重连／注册；warp-cli 不控制内置 WireGuard 节点 |

## 原记录中已校正的部分

- 不复制 `skip-cert-verify: true` 或与用户证书无关的固定 SNI；本包保持证书验证，使用用户自己的有效身份。
- “WARP 是消费级／住宅出口”“老付费账号一定更安全”“验证码风险已全部消除”不能作为保证，公开说明不采用这些结论。
- MTU 1100、关闭 IPv6、拒绝 QUIC 各有适用范围；IPv4 模板不等于整机没有 IPv6、DNS 或 WebRTC 泄漏。
- 原文不同章节的备用顺序有冲突：另一地区既被列为失败对照，又被建议再次作为必经兜底。这里统一为“按当前证据选择独立出口”，不重复购买已无依据的方案。
- 原配置依赖外部 geosite/geoip 数据；公开默认模板用显式规则，避免空环境导入时暗中下载。需要国内分流或额外域名覆盖时另行审阅规则来源与命中。
- 原文的真实配置位置、待清理端口、私人网络服务安排和对第三方网站的未核实指控不进入公开使用流程。

上述是历史经验的工程化整理；当前发布的模板与客户端、TLS设置和规则依赖已有调整，因此必须重新验证，不能沿用历史“已通过”标签。自动化只覆盖配置渲染；故障诊断、付费选择、网络变更与业务验收仍需 Agent 和用户依据证据完成。
