# 项目文件管理

技能包版本：v1.1.2。发布目录、完整 ZIP、指导书与发布清单使用同一版本；assets 中模板和虚构案例的版本仅用于演示。

把项目文件组织成可定位、可接续、可验证的本地资产。方法正文只维护在[项目文件管理作业指导书](references/项目文件管理作业指导书.md)中；按需要读取对应章节，不在本入口复制全部规范。

## 先判断当前任务

1. 明确目标工作区，读取其现有规则、README 和索引，查看登记及实际目录。不用工具进程的当前目录猜测工作区。
2. 新建工作区或项目：读指导书第 2—7 章，使用 [assets/templates](assets/templates/) 的模板。只创建需要的阶段目录。
3. 接续工作、交接或发布：读第 8—9 章，从项目登记定位实际路径，核对状态与成果证据。
4. 接入既有项目：读第 10 章，先盘点与映射，再按授权范围执行。不用示例或模板覆盖正在生效的规则。
5. 检查规范：读第 11—12 章，先运行只读 audit；给出实际发现及未验证部分。

## 工具

需要 Python 3.10 或以上，无第三方依赖。以真实技能目录替换下面的路径参数：

```text
python <skill-directory>/scripts/workspace_admin.py audit --root <workspace-root>
python <skill-directory>/scripts/workspace_admin.py index --root <workspace-root>
```

audit 不写文件；index 只写目标工作区的 PROJECTS.md，且拒绝覆盖没有本工具标记的既有索引。输出 JSON，退出码 0 表示通过，1 表示检查或操作失败，2 表示命令参数错误。详细字段和检查边界见指导书第 7、11 章。

## 关键约束

- 身份字段由使用者填写；没有信息时保持未知，不能把虚构示例当作项目事实。
- 管理登记为唯一结构化来源，索引由其生成；详细交接写 STATUS，README 保留稳定使用说明。
- 路径显式登记且位于工作区内。保留原件、已验收版本和必要证据；发布修订建立新版本。
- 原有 Git、Agent 规则和目录安排先评估兼容；模板是起点，不是授权，也不能覆盖更高优先级约束。
- 迁移、重命名、删除按已确认清单执行；工具不提供这些操作。未确认归属或哈希变化的文件保留并报告。
- 不自动修改全局技能、记忆、平台配置或外部系统。不能把文件检查通过说成业务验收通过。

## 交付检查

入口能打开、登记与索引一致、状态可接续、发布有证据。对未运行的功能明确标注“未验证”。以[虚构示例工作区](assets/example-workspace/README.md)学习文件配合方式；示例只验证管理流程，不构成真实项目成果。
