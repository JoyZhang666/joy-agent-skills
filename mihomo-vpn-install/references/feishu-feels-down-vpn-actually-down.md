# 应用部分断联：先区分直连与代理

一个应用 API 可用而包下载失败，可能是两者走不同链路，并不表示整个网络或整个应用故障。账号登录失效也可能同时存在，需要分开验证。

## 检查顺序

1. 确认失败动作和时间，列出正常与异常功能及其网络路径。
2. 检查 mihomo 进程、HTTP/SOCKS 监听、应用代理引用；日志只取相关错误类别。
3. 对用户允许的无凭据 HTTPS 目标做显式代理与直连对照。
4. 若需要核对应用身份，使用其只读状态接口并遮蔽身份详情；不通过自动发消息来测试。
5. 代理未运行只是一个可能原因；启动、设置自启或升级工具都必须属于当前授权范围。

| 现象 | 进一步核查 |
|---|---|
| 直连可达、显式代理失败 | 客户端监听、代理配置、订阅与节点路径 |
| curl 可达、常驻应用失败 | 应用独立配置、环境、连接池与身份 |
| bot 身份可用、用户身份失效 | 身份与权限单独处理，不重装代理 |
| 两种路径均失败 | DNS、TCP/TLS、目标服务策略，保留多种假设 |

恢复后先做只读检查，再按用户授权验证真实业务。包升级成功或 CLI 返回 sent 都不能独自代表用户侧验收。
