# localhost 502：回环代理对照

本地服务可直连，但环境代理路径失败，可能是回环请求被转给了无法访问本机的上游。`127.0.0.0/8` 是回环地址，不是 RFC 1918 私网段。

## 对照方法

确认本机健康端点是只读请求，再用[回环脚本](../scripts/localhost-proxy-loopback-probe.py)比较直接访问与环境代理访问。脚本只允许 loopback，默认 `/health`，不读取系统日志、不发送业务消息。

```bash
python3 scripts/localhost-proxy-loopback-probe.py --port 8765
```

示例端口不表示用户安装了某个插件。没有 `/health` 时先确认实际只读端点，再通过 `--path` 指定无查询参数的路径。

| 结果 | 含义 |
|---|---|
| 两条路径都 200 | 此端点在当前条件下正常 |
| 直连 200、环境路径失败 | 环境代理配置值得继续检查，不单独证明 mihomo 规则错误 |
| 直连也失败 | 先查服务、端口、端点及访问要求 |

Python urllib 可以用 `ProxyHandler({})` 显式禁用环境代理；并非“没有退出代理的方法”。NO_PROXY 与大小写环境变量的实际效果应按客户端验证。

## 修复边界

优先修正应用的回环直连设置；若确有流量进入 mihomo，再核对本地地址规则。私网、链路本地、IPv6 范围按实际网络政策配置，不一概开放。IPv6 CIDR 使用所选版本支持的规则类型。

修改主配置后校验并经授权应用，确认服务是否支持 reload；不要把 reload 失败自动转成未经批准的 restart。回读并重复同一对照，而不是只看安装工具的绿灯。
