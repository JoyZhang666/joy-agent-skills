# 节点切前基线与切后对比

## 1. 明确测试对象

记录实际 selector 链、当前节点别名、目标业务及测试窗口。`select`、`url-test`、`fallback` 等组行为不同，不能假定 PROXY 自动切换，也不能假定 GLOBAL 一定参与业务路由。

选取用户实际需要的少量无凭据 HTTPS 目标，分别记录 HTTP 状态、TLS/请求耗时与成功次数。业务鉴权测试需单独授权，凭据只留在私有执行环境。

## 2. 建立基线

先对当前路径重复测试，再用单节点 delay API 检查候选；不为探测每个候选而轮流切换整个主代理组。编码节点名和目标 URL，设置单次超时、总体时限和适度并发。

不要依赖包外 `hermes_tools`、个人 MEMORY 或 SOUL 文件。本包脚本与标准工具可直接使用；Agent 专有 API 仅在当前环境明确提供时采用。

## 3. 经授权切换

记录原节点与回滚条件，使用 PUT 切换实际 selector。核对 HTTP 状态并回读 `now`；空响应体不等于成功。等待时间按服务稳定性观察决定，旧连接可能继续沿原路径，不能靠固定睡眠保证迁移完成。

## 4. 用相同条件复测

同一目标集合、样本数、超时及计时口径。报告成功率、延迟中位数/分位数、异常次数，不把失败样本当 0ms 或从排序中悄悄删去。

| 目标别名 | 基线成功/总数 | 切后成功/总数 | 基线延迟 | 切后延迟 | 判断 |
|---|---|---|---|---|---|
| service-A | 待测 | 待测 | 待测 | 待测 | 待测 |

`curl remote_ip` 是 TCP 对端，使用 HTTP 代理时通常是代理地址；它不能单独证明远端业务可用。显式代理测试可用 `--noproxy '' -x http://127.0.0.1:7890`，避免环境 NO_PROXY 意外绕过。

## 5. 收尾

确认最终 selector，报告改善和退化；触发已约定条件才回滚。测试中断时保留脱敏进度与未完成数量，不虚构剩余结果。批量测试边界见[历史统计方法](airport-batch-probe-results.md)。

401/403 不能代替业务成功；200 也要核查响应是否符合业务预期。TCP、TLS、HTTP、鉴权、应用结果分层验收。
