# Python 依赖安装：代理和镜像故障的隔离排查

这是可选运维场景，不是使用本包三个脚本的前提。不要为运行标准库脚本额外安装业务包。

## 先定位

确认当前 Python、虚拟环境、缺失模块和失败类别。缺 venv/ensurepip、源不可达、SOCKS 支持缺失和包版本不兼容是不同问题。检查配置时只在私有终端查看，公开记录不输出带认证的镜像或代理 URL。

pip 优先级是命令行高于环境变量，环境变量高于配置文件；旧稿“全局 pip.conf 覆盖 --index-url”的结论不正确。`PIP_CONFIG_FILE` 设为系统空设备可禁用配置文件加载，但不会自动清除其他环境变量。依据：[pip 官方配置说明](https://pip.pypa.io/en/stable/topics/configuration/)。

## 安装路径选择

优先使用该项目的独立虚拟环境，不修改 Agent 自身环境。安装系统依赖或更换网络路径需要落在现有授权中。无法使用 venv 时，可评估项目私有目录 `--target`，明确后续导入路径和维护责任。

示意流程：选择经过审查的依赖及版本 → 确认解释器与目录 → 排除故障代理/镜像变量 → 在当前进程指定可信源 → 安装 → 在同一环境验证导入和真实功能。

不要把取消全局代理、`--break-system-packages`、忽略证书或修改系统 Python 当默认步骤。它们与当前故障可能无关，并可能扩大影响。

## 输出与验收

只报告包名、版本、错误类别和验证结果；对失败命令的异常文本先检查是否包含私有源或本机路径。不通过打印整个环境字典诊断。能导入不等于业务功能通过，也不证明其他 Agent 已安装同一依赖。
