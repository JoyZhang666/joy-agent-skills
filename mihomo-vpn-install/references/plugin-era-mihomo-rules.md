# 应用插件迁移与代理职责

应用从独立 sidecar 迁移到进程内 SDK，可能改变本地调用路径，但不能据此推定 mihomo 规则或监听端口已经改变。

## 迁移时核对

1. 画出当前应用 → 本地组件 → 代理 → 目标服务的实际路径。
2. 确认是否真的存在 sidecar、由谁启动、哪些组件仍引用其端口。
3. 核查代理设置属于应用配置、进程环境还是系统透明代理，不以插件名称推断。
4. 对相同目标做一次最小的已授权对照，日志和配置输出先脱敏。

## 不做的推断

- 固定端口有监听不证明旧插件未卸载，可能是其他服务。
- CLOSE-WAIT 可以提示连接未被应用关闭，但单独不足以证明连接池死锁或网络根因。
- SSL EOF 不意味着唯一修复是重启网关。
- 某域名应直连还是代理取决于当前网络；旧案例的路由不作为永久规则。

先定位具体组件，再修改最小范围。插件安装、启用、停用、服务重启和残留清理分别按授权执行。没有插件运行环境时跳过该分支，不要求安装包外的私人 Skill。
