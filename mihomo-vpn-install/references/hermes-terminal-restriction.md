# Agent 工具限制与失败后的处理

历史案例中的终端审批层、超时上限和可用命令并非所有 Hermes 或其他 Agent 的共同性质，先读当前工具返回的权限与错误。

- 明确拒绝、要求审批或不允许重启时，停止依赖该动作的后续步骤，使用正式审批流程或让用户在目标主机执行已解释的操作。
- 不通过换 API、改写命令、后台进程、拆分管道或关闭保护来规避拒绝。
- 超时本身不证明被拦截。只读核对服务 PID、启动时间、日志和文件状态，确认动作是否已经发生，避免重复执行。
- 配置已经写盘但服务未加载时，明确写“待生效”，不要报告恢复成功。
- API 修改也属于状态变更，授权范围与对应终端操作一致。

只有在工具允许且任务授权范围内，才可将网络响应保存为受限的本地数据文件再解析；不把远程内容作为脚本执行。

标准交接应说明：目标服务别名、已完成变更、未执行动作、阻塞原因、用户操作步骤及后续验证。不要把身份、主机地址或凭据复制到公开问题单。
