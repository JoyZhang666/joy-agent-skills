# 历史批量探测：统计方法示例

本文件保留旧记录中的汇总数字，用于解释覆盖率和证据边界。不是当前供应商榜单；此次公开整理没有重新连接原订阅，也没有原始全量报告可随包公开核验。

## 已记录结果

旧记录计划测试 171 个端点，完成 98 个，每个重复 3 次：

| 已测样本类别 | 数量 | 占已测样本 |
|---|---|---|
| 3/3 收到预期 HTTP 响应 | 91 | 92.9% |
| 1–2/3 收到预期响应 | 4 | 4.1% |
| 0/3 收到预期响应 | 3 | 3.1% |

覆盖率 98/171≈57.3%，其余 73 个未知。原探测包含未鉴权 HTTP 响应，不能据此声称 92.9% 的节点可完成业务或供应商可信。因四舍五入，占比和可能略超 100%。

原文详细节点名、域名前缀、端口组合、个人选择与真实原始文件路径已移除；公开包不提供任何可连接节点信息。

## 可复用方法

1. 先跑一个授权端点，确认计时口径、错误分类和输出不泄密。
2. 根据单次最坏超时估算批次规模，为退出和写入预留时间；不把“30 个节点”当通用上限。
3. 每批保存去标识化记录，包含已测/未测、成功/失败、样本数和异常类别。
4. 超时和失败保留在分母；不同业务目标分别统计。
5. 先评估成功率，再比较延迟和稳定性；吞吐量需要单独测量。
6. 清理只针对本批创建的临时配置和明确记录的进程，不使用按名字匹配的全局 kill。

入口地址、出口地域和品牌标签不是同一个概念。不能仅凭域名前缀或国旗推断真实出口，也不能把一次端口连通当信任评估。
