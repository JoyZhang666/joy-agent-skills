# 下载来源与订阅格式检查

## 二进制下载

优先使用 [mihomo 官方 Releases](https://github.com/MetaCubeX/mihomo/releases)。直连失败时可在可信联网机器下载同一资产后传入，比较同一压缩文件的官方摘要或签名；不要拿解压后文件哈希与压缩包摘要比较。

第三方镜像只提供传输途径，不构成真实性证明。没有官方校验依据时保留待核实状态，不因另一个包也标相同版本就接受哈希差异。不向镜像、在线转换器或测速网站发送真实订阅 URL。

## 订阅内容

由用户通过私有配置提供订阅，下载到访问受限的目录。不将 URL 放入截图、Shell 历史、调试日志或进程命令参数；可使用私有 curl 配置文件（600 权限）指定 URL，并禁止重定向至未经确认的第三方。

不要 `head`、`cat` 或直接打印 Base64 解码结果。Content-Type、首字符和文件大小都不足以确定格式：

| 内容 | 检查方法 |
|---|---|
| Clash YAML | 用支持 YAML 的安全解析器在本地验证结构，输出节点数量而非整行内容 |
| SS URI 或 Base64 列表 | 严格解码、验证每条协议与字段，只输出格式和计数 |
| HTML/JSON 错误 | 仅报告错误类别，不复制可能含 token 的正文 |

生产使用 YAML 解析器或订阅转换程序时须另行确认依赖；本包不假设 PyYAML 已安装，也不提供远程订阅转换服务。mihomo 接受的订阅格式以所选版本验证结果为准。

## HTTP 403 与空节点

403 可能来自账号订阅状态、凭据失效、访问策略或边缘代理，不能直接归因于 WAF。通过服务商后台和脱敏错误类别确认；不靠自动轮换地址绕过拒绝。

收到 HTTP 200 也可能得到错误页。节点数为空时依次查解析、provider 状态、`use` 关联、`filter` 与 `exclude-filter`，避免反复删缓存或重启。API 刷新路径见[节点诊断](vpn-node-routing-diagnosis.md)。

新旧 URL 在本地比较，只报告是否相同。相同 URL 不代表 token 有效，也不能靠重复保存来修复失效凭据。
