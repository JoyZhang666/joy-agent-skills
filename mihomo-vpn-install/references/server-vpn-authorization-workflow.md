# Linux 安装与配置工作流

适用于经用户授权的 Linux 主机。默认采用显式 HTTP/SOCKS 代理；已有运行服务时先审查差异，不能覆盖重装。配置示例使用标准安装路径，用户可选择其他路径。

## 1. 预检查

在目标主机核对 `uname -m`、`uname -r`、磁盘空间以及 `ss -ltn` 中的端口占用。7890、7891、9090 是本包示例端口，不是必须值。确认安装方式、服务运行用户与现有网络依赖。

### 先确认订阅或节点来源

新安装时，Agent 必须先确认是否已有可用节点来源，不能默认用户已经填写订阅：

- 已有私有配置且获准读取：在本地核对其类型及节点来源，不重复索要 URL，不回显凭据。
- 没有可用配置：主动询问：“你已有代理订阅 URL，还是独立节点配置？我可以先帮你准备一个文件，再一步步告诉你如何填写。如果文件操作不方便，也有直接在当前聊天提供订阅链接的备用方式。”随后按下面的具体步骤引导。
- 用户尚未提供：标记“等待节点配置”；可继续已授权的二进制准备，但不得用占位符启动服务，也不能报告代理配置完成。收到配置后从此步骤续接。
- 只有独立节点配置：不强求订阅 URL。按所选 mihomo 版本采用内联节点或本地 provider，并同步策略组引用；不能直接沿用本包的 HTTP 订阅模板。

本包模板使用 HTTP provider，因此采用该模板时必须有有效订阅 URL。有效订阅只是前提，不等于代理连接成功。

只诊断时停在证据收集，不自动下载、安装或重启。必要的变更记录见[风险模板](risk-analysis-template.md)。

### 如何提供订阅链接

先确认用户正在操作的电脑、安装目标（本机还是远程服务器）、Agent 能访问的位置，以及读取和下载验证的授权范围。不要把“仓库外私有文件”当作小白用户已经理解的术语。

**方式一：协助准备文件（优先）。**

1. 在已授权且可写的位置选择项目目录之外、未共享且不自动同步的目录；核对真实路径和访问权限后创建新的空白 `subscription-url.txt`，不覆盖已有文件。只向所需用户或服务开放权限；Windows 核对访问权限，Linux 可使用目录 700、文件 600。“项目外”不自动等于安全。
2. 告诉用户这个文件只用于本次代理配置，不会上传 GitHub。提供实际存在、可点击的完整路径；不要让用户自行猜路径或照抄占位路径。如果没有文件创建权限，按实际系统提供手动步骤，不声称已创建。
3. 对 Windows 用户这样说明：“点击上面的文件，选择用记事本打开；把服务商给你的完整订阅链接粘贴成一行，不加引号；按 Ctrl+S 保存，关闭窗口，再回复‘已保存’。不要发送文件内容截图。”若点击不能打开，指导用户在记事本中通过‘文件 → 打开’选择刚才给出的确切路径。
4. 用户保存后，按授权读取；遇到空文件或多行内容，只报告问题类别，请用户修正，不回显链接。该文本文件是输入凭据，不是 mihomo 的 YAML 配置；由 Agent 将其用于后续私有配置。
5. 若安装在远程服务器，说明本机文件不会自动出现在服务器上。在用户已授权的连接或文件传输方式中受限传递，并核验目标文件权限；不可把 URL 放进远程命令参数、日志或截图。没有可用传输方式时说明缺口，不能假装远端已读取。
6. 配置完成后说明输入文件是否仍需保留；一次性输入文件的删除按已确认授权执行，不自动删除持续运行所需的配置。

**方式二：用户知情选择在当前聊天提供 URL（备用）。**

文件操作不方便时，说明：

> 订阅链接往往含有访问节点配置的 token，相当于一把钥匙。如果你选择把完整链接发到当前聊天，它会进入聊天记录，平台可能保存它。接受这一点的话，可以直接在这里发送；请不要发到公开评论或群聊。也可以继续使用文件方式。

用户在说明后选择并发送，即可按已有配置授权继续，不反复索要同一链接。Agent 不承诺平台不保存、自动清除或端到端保密；不在回复、公开报告、代码、Git 提交或日志中复述链接，也不把链接放进可见的命令参数。落盘及请求工具的参数也可能被记录，必须考虑其记录行为：优先使用宿主已提供且核实可用的敏感输入/凭据能力；没有这类能力时说明工具参数也可能留存，由用户选择接受该处理方式或回到文件方式。工具不允许接收凭据时遵守限制，不绕过。

只把接收的 URL 用于已授权的配置和验证，保存到访问受限的私有配置；不转发给第三方转换器。聊天方式只解决输入便利性，不替代远程访问授权或安全传输。若用户已经主动发来了链接，不引用其内容，简要说明留存风险并确认后续处理范围，不让用户再发一次。

## 2. 获取二进制

从 [mihomo Releases](https://github.com/MetaCubeX/mihomo/releases) 选择与目标架构、CPU 指令集及系统兼容的明确版本。不要仅凭旧案例的内核号决定下载文件，也不默认追随 latest。

按[下载检查](github-mirrors.md)验证发布者与同一资产的校验信息，再解压、授权执行和查看版本。下载成功不等于内容可信；不要忽略校验失败继续运行。

## 3. 配置私有工作目录

1. 选择二进制位置（例如 `/opt/mihomo/mihomo`）与私有配置目录（例如 `/etc/mihomo`）。
2. 采用 HTTP 订阅时，将[注释模板](mihomo-config-annotated.yaml)复制到私有配置目录，从已确认的私有来源填写订阅及独立 controller 密钥；采用独立节点时使用相应的私有配置并设置独立 controller 密钥；按用户选择的提供方式接收，不要求重复发送秘密。文件只向服务用户开放，Linux 可使用目录 700、文件 600。
3. 模板中的 `.invalid` URL 不可用；真实配置不能存回 Skill 或 Git 工作目录。确认缓存目录也受限。
4. 使用 provider 的 `use` 引用；筛选前先在本地确认节点命名。`filter` 是筛选，不保证选中某个默认节点。
5. 明确是否使用 GEOIP/GEOSITE；如果使用，其数据库另行按可信来源配置。本包最小模板不依赖它们。

配置检查可能触发订阅或数据库访问，须在已授权主机与网络范围内运行，并保护输出：

```bash
/opt/mihomo/mihomo -t -d /etc/mihomo
```

配置与节点来源验证通过后，才进入服务启动：

- 采用订阅时，经授权读取或下载，拒绝 HTML/JSON 错误页；采用独立节点时，读取获准使用的私有配置。两者均确认所选版本支持的格式及必要认证字段，解析后的节点集合非空。
- 检查 provider、策略组及节点引用可解析；配置校验成功后，仍须在启动后回读实际加载的节点集合。
- 下载、解析失败或节点为空时停止启动，报告脱敏错误类别并等待修正；禁止反复重启或将 HTTP 200 当成订阅有效。
- 不打印 URL、节点名、密码或订阅正文。下载与格式检查见[订阅检查](github-mirrors.md)。

## 4. 服务定义

以下是 systemd 单元示例，需要安装授权。没有 `ExecReload`，因此不能假定 `systemctl reload` 可用。

```ini
[Unit]
Description=Mihomo Proxy
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/etc/mihomo
ExecStart=/opt/mihomo/mihomo -d /etc/mihomo
Restart=on-failure
RestartSec=5
UMask=0077

[Install]
WantedBy=multi-user.target
```

按主机安全策略配置服务用户及权限；TUN 权限要求与仅显式代理不同。保存单元后经授权执行 daemon-reload、启动服务；开机自启是单独的持久设置，按用户选择决定。

## 5. 验证与应用接入

- 服务进程、配置路径和监听地址符合预期，controller 仅回环可达。
- 回读 provider 或内联节点集合，确认非空、策略组引用正确、实际选中的节点存在；再测试显式代理和目标业务。未通过时记录失败层，不报告代理连接成功。
- 对同一无凭据 HTTPS 目标分别做直连和显式代理测试，区分网络响应与业务成功。
- 应用代理设置按实际应用生效位置配置；交互 shell 的环境不代表 systemd 服务环境。
- 需要本机访问的地址配置合适的 `NO_PROXY`；它不能替代 TUN 路由检查。
- 启用健康检查会产生周期网络请求，应在确认目标、频率和流量后开启。

## 6. 重载、回滚与卸载

修改前保留私有备份；区分运行配置 PATCH、配置重载 PUT 和服务重启，按[官方 API](https://wiki.metacubex.one/api/)及当前版本处理。重载后回读 provider、selector 和目标应用状态，失败则停止扩大变更。

回滚恢复本次改动的字段或已确认的备份，再按同样验证流程检查。不能把 GET 返回的局部状态直接当完整配置备份。卸载时列明服务、文件和其他应用引用，取得该范围授权后逐项处理；不提供全目录递归删除的一键命令。
