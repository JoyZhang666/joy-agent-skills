# 应用 TLS 故障与新订阅隔离测试

适用于 Codex/OpenAI 或其他 HTTPS 应用在代理下失败的排查。应用的真实请求地址、鉴权方式和配置项由当前应用确定；不要把一个旧域名当所有版本的默认后端，也不擅自改 API base URL。

## 先区分失败层

| 观察 | 能支持的结论 | 不能支持的结论 |
|---|---|---|
| DNS 解析失败 | 当前解析路径有问题 | 必然是上游 DNS 故障 |
| TCP 连接失败 | 当前端点不可达 | 必然是节点停服 |
| SSL EOF / SYSCALL | TLS 或底层连接异常 | 已证明某协议不支持 ALPN |
| HTTP 401/403 | 收到 HTTP 响应 | 已通过鉴权、业务可用 |
| 健康检查 204 | 测试目标响应 | 所有应用目标都正常 |

用同一目标进行直连/代理、不同节点、重复样本对照；保留失败证据并核对实际应用代理链。不要关闭证书验证来“证明修好了”，不要把 TLS 错误一律归因于地区、供应商品牌或某种协议。

## 解析与路由

DNS 返回地址会受 CDN、地区和配置影响，不能用静态 IP 段白名单证明污染。比较当前解析链、可信解析结果、实际 TLS 证书与路由证据。代理是否远端解析取决于协议与配置，不是一条通用保证。

查看服务真实的代理配置位置；shell 与常驻服务环境可能不同。只输出变量是否设置或经批准的无认证回环地址，不输出完整环境和代理认证信息。

## 新订阅的三种处理路径

| 方式 | 范围与前提 |
|---|---|
| 新增独立 provider | 经授权改配置，保留原 provider 和可恢复备份，回读新集合与组引用 |
| 独立测试实例 | 使用独立端口、私有配置和独立进程；不抢占生产监听，不继承生产 TUN |
| 暂不接入 | 来源或授权不清楚，保留现有配置并报告待核实项 |

不向第三方在线转换器发送订阅。Base64 SS 列表仍包含密码，解码只在私有内存或受限文件中进行。

## SS URI 解析注意事项

- 支持的格式要明确区分：编码的 `method:password` 加 `@host:port`，或整个主体编码；不要把两种格式混用。
- 补齐需要的 Base64 padding，使用严格解码，拒绝无法确认的输入，避免忽略错误后接受损坏凭据。
- 按格式规范处理最后一个 `@`、IPv6 方括号、端口范围、URL 编码片段及可选插件参数。
- 节点名也可能识别供应商，公开输出使用 `node-001` 这样的别名；不打印完整 URI 或解析后的字典。
- 若需要可执行转换工具，选择经过审查、支持所用协议的实现；本包不把历史示意代码当完整解析器。

## 可选客户端与环境

[shadowsocks-rust](https://github.com/shadowsocks/shadowsocks-rust) 是可选独立客户端；按上游选定版本、资产和校验信息，不猜校验文件 URL 或根据星标数认定安全。旧 Python shadowsocks 的历史兼容性问题不能外推到所有现有实现。

创建专用测试目录，Linux 权限 700，配置文件 600。以进程对象/PID 精确跟踪自己启动的测试实例，使用 try/finally 停止和等待该进程；异常消息只输出类别，避免带出节点地址和密码。进程无法确认归属时停止清理。

## 批量与退出

先验证单个样本，再按执行环境的真实时限分批；每批写脱敏结果。普通 finally 不能保证在强制终止或断电时运行，因此记录私有临时目录，恢复后先核实进程已停止，再使用[清理预览工具](../scripts/ss-probe-cleanup.py)。

不要批量删除整个临时目录或 `pkill` 全部同名代理进程。完整的切换验收见[对照工作流](probe-baseline-switch-compare-workflow.md)。
