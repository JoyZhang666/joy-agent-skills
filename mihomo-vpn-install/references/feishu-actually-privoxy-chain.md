# 应用错指 Privoxy 代理链

## 可复用案例

应用配置仍指向旧的本地代理端口，而新 mihomo 已监听另一个端口。单独使用 mihomo 能收到目标 HTTPS 响应，应用却报 `ProxyError` 或 `500 Internal Privoxy Error`。

```text
应用 → 旧 Privoxy 端口 → 旧 SS 客户端 → 失败
手工对照 → mihomo 端口 → 目标服务 → HTTP 响应
```

两个请求的代理链不同；修改 mihomo 分流规则不会自动修复应用中的代理地址。

## 诊断

1. 核查应用实际加载的代理配置，勿把当前 shell 设置当应用进程设置。
2. 查看必要的监听端口与错误类型，不复制整份配置、环境、服务日志或鉴权响应。
3. 使用无凭据目标对照两条链路；有鉴权时只记录结果状态，不能显示 token。
4. 报告当前应用使用的代理别名与预期别名，不在公开记录中显示主机名。

## 修复与验收

经授权只更新错误引用，备份并检查差异；按应用支持的方式重新加载，需要重启时先确认影响。分别验证代理连通、应用鉴权及真实业务；向他人发送测试消息需要明确发送授权。

旧服务的卸载是另一项操作，先检查是否仍有其他使用者，不根据安装日期或一次失败就认定可删除。
