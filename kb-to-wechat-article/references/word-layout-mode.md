# Word 定稿：保留原文，并给出能继续的路线

用户给的是定稿时，不改写、不删空段或标点，不把换主题当成原格式保真。先讲：“我先检查文稿。普通文字可以保持可编辑；复杂版式也有图片方案，我会说明差别后让你选。”

## 先确定用户想保留什么

- **文字可编辑优先**：支持范围内的 DOCX → 包内解析 → 本地 HTML → 手机宽度预览。保留逐段文字、换行、空段、直接设置的标题/粗体/斜体/下划线/对齐、内嵌 PNG/JPEG 顺序及原图片字节。默认 `original` 不套主题；它只保留已支持的格式，不能复现 Word 字体、分页及样式继承。
- **复杂版面外观优先**：保留原稿，生成 110 mm / 18 磅独立手机版副本 → 原编辑器核对重排并导出 PDF → 本包检查宽度/小字并逐页转 PNG → 人工按序放入公众号草稿。表格、公式、分栏和浮动图随整页画面保留，代价是图中文字无法直接编辑、选择或检索；不是功能无损。详见 [复杂文档补救步骤](word-fidelity.md)。

任意 Word → HTML → 公众号，版式和功能全部无损，不是本包承诺。先约定保留范围，再核验；不要擅自将可编辑内容改为图片。

## 普通 DOCX 本地流程

安装和命令在 [Word 工具说明](../tools/word-mode/README.md)，依赖分类见 [依赖地图](dependency-map.md)。

1. 选定用户自己的工作文件夹，展示实际路径。保留原件，以全新文章目录运行 `prepare.py`，得到 `source.docx`、`source.html`、`source-check.json`、`source-paragraphs.json` 及 `media/`。
2. 运行 `render.mjs`，默认 `original`。用户明确想换风格才用已安装主题。原文或原图变化后重新建档并确认，不能修改校验数据来强行通过。
3. 用 `capture.cjs` 在临时浏览器生成 390px 手机宽度截图。断图、横向溢出、页面过长返回失败。保留 HTML，按工具说明排错。
4. Agent 实际看图，再请用户确认字、图、顺序和手机可读性。程序校验不是视觉验收。主题台账从空白模板开始，只记录实际验收的主题。
5. 交付 HTML、截图和原图。**Word 多图自动入草稿箱尚未实现**；按 [人工交接](word-fidelity.md#把页面图片放进公众号草稿箱) 的原则在后台粘贴支持的正文、逐张插图并预览。不能把本地图片路径当已上传图片，也不能用仅支持单图的 `scripts/push_guarded.py` 绕过限制。

## 解析失败后必须继续帮助

说清“哪种结构暂不支持、原文件未修改”，随后按 [故障处理表](word-fidelity.md#遇到不同问题具体怎么办) 给出下一步：修订先确认最终视图；旧 `.doc` 在原编辑器另存 `.docx`；复杂表格/公式/分栏先制作手机版副本，再转 PDF 页图；缺字体先在原电脑核对 PDF。不得只让小白自己寻找转换器，不把私人文档送到未知在线网站。

`publish-guarded.mjs` 仅为旧入口的阻断提示，不读取密钥或联网；`SKIP_COVER=1` 不是受支持的无封面发布方案。真实草稿能力须独立联调，不能用语法或本地截图代替。
