# 复杂 Word 也能继续：先选保留方式，再交到草稿箱

如果你已经花时间做好 Word 排版，AI 不应只说“不支持”。它应告诉你卡在哪里，再带你走适合的一条路。

## 先用一句话选路线

> 你更希望“文字以后还可以修改”，还是“尽量保持现在看到的版面”？普通文字可走可编辑路线；复杂版面可选择先做手机版副本，再转成高清页面图片。图片可以放入公众号，但里面的字不能单独修改、复制或搜索，手机上也可能需要放大。你选哪一种？

已有明确偏好就沿用。图片方案必须获得用户对交付形式的选择，不能静默降级。若要求全部可编辑且与任意 Word 完全相同，要说明本包无法保证两者同时成立，协助选择关键保留项，不承诺万能转换器。

## 从 Word 到高清页面图片

全部本地操作，不必上传文稿到在线转换网站。AI 先展示用户自己的实际保存位置，下列名称只是示例。

1. **保留 Word 原件。** 另存用于发表的副本。修订稿先确认哪些修改要接受或拒绝，批注是否公开由你决定；“无标记”可能只是隐藏，不能当作清理完成。
2. **制作手机版副本。** 让 AI 用包内 `mobile-copy.py` 生成全新目录中的 `mobile.docx`：页面宽 110 mm（11 厘米，含留白），左右各 5 mm，正文至少 18 磅、1.5 倍行距、单栏。保留原文、原图字节及其他包内资源；普通内嵌图片超宽时按比例缩至正文宽，浮动图和表内图片仍需核对；页高沿用原稿，先在编辑器核对分页。若工具拒绝某种结构，按下方手动步骤继续，不让用户自己寻找转换器。
3. **在 Word 中检查显示。** 看表格是否完整、公式是否正确、图有无错位、字体是否正常。缺字体优先回原电脑导出；替换字体须先确认外观变化。
4. **导出 PDF。** Windows Word 通常是“文件 → 导出 → 创建 PDF/XPS”，也可“另存为 → PDF”。选“标准”质量，选项中确认“文档”还是“显示标记的文档”。公开文章通常用已确认的最终正文，AI 不能替你接受修订或删批注。不同版本名称以页面为准。
5. **打开 PDF 核对。** 对照 Word 检查页数、表格、公式、图片、页眉页脚、修订及批注。错误先修正；可能遇到字体替换，不能跳过这一步。
6. **让 AI 整页转图。** 告诉 AI PDF 位置，并确认这是刚导出的已核对版本。AI 按 [工具说明](../tools/word-mode/README.md) 运行 `pdf-pages.py`，保留 `source.pdf`，生成编号 PNG、`article.html`、`preview.html`、三种宽度的预览和 `mobile-check.json` / `manifest.json`。页面宽度不是约 110 mm 时先停止；小字、边缘文字或无法测量的页面会明确提示待复核，不能只看图片生成成功。不是只提取内嵌图片；字、图、表格一起渲染。默认不裁页、不拼成长图、不套主题。
7. **核对交付。** AI 逐页查看页数、顺序、边缘、缺字和空白，再帮助你按手机宽度查看。Word→PDF、PDF→PNG、PNG→微信三处分别核对，不能用一次哈希检查代替。

## 手机版参数与手动接续

默认宽 110 mm、左右各 5 mm、正文 18 磅、1.5 倍行距。页高按内容分页，沿用原高度后在编辑器核对，不强求 A4 比例。尾页留白过多时，在副本中调整页高并重导出，不直接裁掉不确定的内容。此为本包工程默认值，不是微信官方尺寸规定。仅提高 DPI 或把 A4 PDF 整体缩小，均不能改善文字与页面的比例。

工具无法处理时，AI 一次只带用户完成一步，并给出实际副本路径：

1. 在原编辑器点“文件 → 另存为”，保存为一个新文件，例如 `mobile.docx`；保留原件。
2. 在 Word 点“布局 → 大小 → 其他纸张大小”，把宽度填为 **11 厘米**；文档有多节时应用到整篇。再到“页边距 → 自定义页边距”，左右各 **0.5 厘米**；设为单栏。其他编辑器以当前界面为准。
3. 选择正文，在“开始”中设 **18 磅**；标题可更大，保留原有粗体与颜色。段落行距选 **1.5 倍**。表内字、文本框和脚注也要检查，不能只改正文表面。
4. 查看整篇：宽表拆成有重复表头的小表并核对每个单元格；不要缩字号硬塞、横向裁掉列或凭 AI 重写数字。浮动图、文本框、公式、分页和标题层级须对照原稿。移动、拆分前展示具体变更；保留所有内容。
5. 导出 `mobile.pdf`，重新检查后转图。如果用户必须保持原 A4 分页和全部位置，说明它与手机版重排有取舍；原 PDF 单独保留，不冒称两者同时完全一致。

副本工具不启动 Office，不自动导出 PDF，不下载字体；修订/批注、外部链接资源、宏和嵌入对象等会停止并提示回编辑器处理。外部资源如需使用，由用户在可信原编辑器中确认内容并嵌入副本，或手动制作已核对的手机版 PDF；不要关闭检查绕过。

## 什么时候可以交稿

- `mobile-layout.json` 的 `needs_editor_review` 表示副本已生成，尚待原编辑器核对，不是失败也不是最终验收。
- PDF 默认 200 DPI，110 mm 页图约 870 像素宽。文件更清晰不等于字更大。
- `manifest.json` 的 `complete` 只说明页图生成完整；同时查看 `mobile-check.json`。程序按 320 像素视口、左右各 16 像素留白，估算可提取文字的显示字号；低于 16 像素或越出页面会提示对应页码，不记录文章正文。
- `checks_passed` 不是视觉验收。公式上下标、图片内文字、重叠及字体替换需要人工核对；图片/轮廓文字无法测量时是 `needs_review`。AI 查看所有 320/390/430 预览，给出具体补救，再请用户确认；不得改写程序报告伪造自动通过。若仅剩无法测量的内容，可在私人交接中另记用户实际目检结论后继续人工交稿。
- 320/390/430 是本地预览宽度，不是微信强制规格。正式交稿前仍需在微信手机预览中确认无需放大能读清正文、无裁切/漏页；不得把本地检查称为微信已验收。


## 把页面图片放进公众号草稿箱

这是 **人工或用户授权后由可用浏览器工具协助的路线**，不需要 AppSecret 或固定 IP。以下按钮名称是引导，未替用户完成后台实测；AI 每步查看当前页面再继续。

1. 打开 [微信公众平台](https://mp.weixin.qq.com/)，用有权限的管理员/运营者微信扫码登录。这是文章编辑后台，与找 AppID 的开发者平台不同。
2. 根据页面进入草稿或新建图文，填已确认标题。
3. 从正文图片入口选择本地上传，按 `page-0001.png`、`page-0002.png` 顺序插入。多选后仍核对顺序，不假设后台一定排序正确。`article.html` 仅为本地对照，里面的本地图片路径不代表已上传。
4. 对照清单检查漏页、重复、方向、裁切和上传失败；按后台当前要求配置封面，不把整篇多页稿当一张封面。
5. 用户决定是否发送手机预览。检查小字、宽表、清晰度和页间空白；微信压缩后看不清则回 Word 做手机版，不能称压缩也无损。
6. 保存为草稿，回草稿列表确认存在。**草稿不等于群发。** 结果不明确先查列表，避免重复创建；未经指令不发表。

## 遇到不同问题具体怎么办

| 现象 | 可以继续的处理 |
|---|---|
| 表格、公式、分栏、浮动图无法解析 | 选择 PDF 页图；需要可编辑时，另建手机版副本重建对应内容并逐项核对，未验收不称完成 |
| 有修订或批注 | 让用户确定最终正文或审阅版，在副本处理，导出后查看；不自动接受全部修订 |
| `.doc` 或扩展名不对 | 原 Word 另存真正的 `.docx`，不是改后缀；复杂版式直接导出 PDF |
| 断图或截图失败 | 核对原 Word/PDF，再检查本地图片和浏览器路径；修复后重新生成，不报成功 |
| PDF 加密或含交互表单 | 请所有者从原编辑器导出已确认的普通静态 PDF，不破解密码；表单填写内容先核对 |
| 页数、尺寸或图片超工具上限 | 原件保留；用户在编辑器按章节导出，记录页码并核对衔接，不静默丢页、降分辨率或截断 |
| 字体替换、公式异常 | 优先原电脑导出；同意后替换已有字体再导出，不擅自下载或分发商业字体 |
| 手机字小、宽表难看 | 按 110 mm / 18 磅重排副本；宽表拆分并重复表头，核对数据，再导出；不裁列或缩小字体硬塞 |
| 微信提示图片太大 | 以后台当前限制为准；保留原图，同意后压缩副本并手机复核，仍不可读则回原稿分章或调整版式 |
| 没有 Word | 询问是否已有能正确打开原稿的 WPS/LibreOffice，核对后导出 PDF；不同软件可能重排。也可请原作者导出，不擅自安装大型软件 |

## 原理与核查边界

HTML 不支持 Word 的全部排版功能，转换器可能依赖专有 CSS，不能推断微信保留。PDF 页图保留用户确认的视觉画面，不保留编辑语义、链接点击、辅助阅读结构，也不保证微信处理后每个像素不变。
