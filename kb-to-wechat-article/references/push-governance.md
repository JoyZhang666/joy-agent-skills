# 可选：把文章送进公众号草稿箱

这一步把文章和图片发到你的微信公众号后台，**不会公开群发**。不需要此功能时，拿到文字稿就已完成基础交付；也可以自己在公众号后台粘贴、排版。

先选方式：**人工后台编辑/插图保存草稿**不需要 API 权限、AppSecret 或固定 IP，按 [人工交接步骤](word-fidelity.md#把页面图片放进公众号草稿箱) 操作。以下密钥及接口检查仅适用于**普通单图自动上传**。完整 API 配置见 [公众号与网络新手指南](wechat-account-and-network.md)。

## 给第一次使用的你

AI 一次只带你做当前一步，不要让你先填满一张技术表：

1. **确认自动接口条件**：确认账号管理权及素材/草稿接口权限。没有 API 权限时可继续人工后台交稿，不要求购买服务；连后台编辑权限也没有时，交付本地文件并请有权限的运营者接手。
2. **先看稿件**：确定本篇标题、作者、正文、封面和排版预览。AI 说明本次会发送哪些内容，等你明确同意后才发送。
3. **再配置秘密信息**：AppID 是账号标识，AppSecret 是接口密钥。AI 按当前官方说明引导你在执行机器的私有环境设置中填写 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`，不让你贴到聊天、文章或 GitHub。只有账号管理员能操作的页面，由你本人完成。配置或重置密钥可能影响其他程序，不能擅自重置。
4. **核对 IP 白名单**：若平台要求，只添加真实执行机器的出口 IP；浏览器所在电脑和实际运行 AI 的服务器可能不同。AI 没有权限就明确停在这一步，不猜地址。
5. **发送后核对**：AI 报告“已进入草稿箱”或具体阻塞。你在后台查看标题、图片、封面和手机排版，最后由你自己决定是否公开发表。

外部条件随微信接口和账号权限变化，开始配置前查看 [微信公众平台](https://mp.weixin.qq.com/) 的当前设置与 [官方接口文档](https://developers.weixin.qq.com/doc/offiaccount/Getting_Started/Overview.html)。本包不包含微信账号、密钥或排版服务。

## 本包自动入口的范围

当前只支持**普通单篇、正文单图**的已审阅 HTML，固定使用文章目录内的 `cover.png`。多图、图文消息组、贴图模式、复杂 Word 排版不交给此入口；保留本地文件并使用后台人工编辑。

预览须是正文 HTML 片段，样式写在元素内部（inline CSS），唯一图片写成 `<img src="cover.png">`。禁止脚本、外部 CSS 和远程图片资源；网页完整外壳需要经本地检查后提取正文片段，不能随便删除标签改变内容。

排版可用文颜或其他当前可用工具生成本地 HTML；文颜是可选第三方工具，不随包分发，也不由本包自动安装。先查看当前 `wenyan --help` / `wenyan render --help` 确认可用方式。文颜的发布命令不属于本包安全守卫，不能用它绕过检查。

辅助脚本需要 Python 3.10+；图片检查需要 Pillow，见 [依赖列表](../requirements.txt)。AI 在已授权范围内为本项目准备隔离的依赖环境，不能悄悄全局安装。没有依赖时仍能写文章，但不能把未执行的自动检查报告成通过。

## 给执行 AI 的规则

脚本路径相对 Skill 安装目录；`ARTICLE_DIR` 是用户工作目录中本篇文章的**真实绝对路径**。实际执行前把示例占位符替换为已核对地址并正确引用空格；不要让小白自己替换路径。不要在安装目录下创建稿件。

```text
python "<SKILL_DIR>/scripts/push_guarded.py" "<ARTICLE_DIR>" --theme "<已选择主题>" --dry-run
```

不带 `--approve-upload` 时只做本地检查，不读凭据、不联网。`--dry-run` 不是用户确认，也不能记成已推送。这个自动入口不接收临时 CSS；最终样式应先落入已确认的预览 HTML。

申请发送前，在本篇 `workflow-state.json` 保存实际确认状态：正文定稿、表达检查、质量检查、封面确认、主题确认与 `selected_theme`。仅用户实际同意本次上传时才设 `upload_confirmed=true`、`delivery_mode=wechat_draft`，并把用户看过的 `article.md`、`cover.png`、`previews/<theme>.html` 的当前 SHA-256 写入 `confirmed_artifacts`。脚本会检查这些哈希，任何产物改动都须重新核对受影响的确认。哈希由 AI 生成；不让用户计算，也不替用户填同意。

```text
python "<SKILL_DIR>/scripts/push_guarded.py" "<ARTICLE_DIR>" --theme "<已选择主题>" --approve-upload
```

上传前执行预检、HTML 残留检查及路径约束，拒绝越界路径、符号链接与未支持的图片来源。只传用户已确认的正文和单张封面；不扫描私人目录、不读取未知账号 token 缓存。执行过程使用同目录排他锁，已存在草稿收据或结果不明时阻止重复新建。

## 结果不明或失败怎么办

| 情况 | 正确处理 |
|---|---|
| 缺少依赖、当前确认、预览或质量检查失败 | 停止上传，给出本地修复建议；不改确认来让检查变绿 |
| 已有草稿收据 | 使用原草稿核对/回环，不再创建新草稿 |
| 超时、连接中断或成功响应无法解析 | 保留结果不明记录，先由用户检查后台；不删标记重试，不假定后台没写入 |
| 后台已有新修改 | 按 [回环协议](draft-loop-protocol.md) 拉回合并，禁止覆盖 |
| 权限、网络或证书问题 | 只记录脱敏错误类别，保留稿件；不改代理、不重启服务、不将真实内容提交第三方诊断站点 |

收据只能证明接口接受了请求。基础回验检查标题、作者、正文等有限字段；封面身份、图片顺序、样式和手机视觉效果仍需实际检查。必须分别说明已验证与未验证项，不能用退出码 0 宣称完整发布验收。

挂起只记原因与下一步；用户明确要求预约且宿主支持时才能创建有限任务并验证回执。没有调度能力就说“下次继续”，不创建默认心跳，不因等候超时擅自发送。
