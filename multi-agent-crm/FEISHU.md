# Feishu test Base setup

Use a dedicated, newly created test Base. Keep a blank starter table or remove it manually if appropriate. The initializer accepts at most one empty starter table and creates the eight model tables beside it. Each link points to the native Feishu row of its target. Store the mapping and coordinator state outside this package.

1. Install Python 3.10+ and a compatible official `lark-cli` with the typed `base +table-list`, `+table-create`, `+field-list`, `+field-create`, `+record-list`, and `+record-upsert` commands. Sign in using the operator's own user profile and grant that user the required schema and record access on the disposable Base. The adapter always invokes the CLI with user authentication. It does not store an access token.
2. Set `CRM_FEISHU_BASE_ID` in the operator's environment to the Base identifier. Verify the target explicitly before any initialization. Create a private directory for state. Run `python feishu.py init --mapping /path/to/private/mapping.json`, using a path appropriate to the host. Only one initializer should run. Keep the mapping's table identifiers and schema digest after initialization. Re-running with the same mapping checks field types and native link targets. If initialization lost a create response, inspect the unmapped table before attempting another run. The initializer does not delete or replace existing tables.
3. Run `python crm.py --db /path/to/private/coordinator.db init --feishu-config /path/to/private/mapping.json`. Supply the same Base identifier and authenticated CLI environment to each invocation that uses this database. Follow the operator guide to enroll separate CRM actors. These actor profiles govern CRM attribution; where both use one Feishu login they share that user's platform permissions.
4. Test a synthetic organization and stage first, then an opportunity linked to both. Use a current version/hash, read the resulting row through the adapter, and compare the audit record. Test a stale update, duplicate key and interrupted delivery before enabling business use. The SQLite coordinator belongs on a single host with serialized writes; separate local coordinator files pointed at the same Base cannot coordinate concurrent edits.

Field names in Feishu use the model keys directly. Numbers and dates are native fields. Single and multi-valued references use native link fields; the schema and CRM validation enforce the link count. Do not rename managed fields or allow concurrent direct edits during coordinated writes. Manual edits can invalidate before-images. The adapter uses paginated reads; an unavailable or unreadable table is an error. External record writes may have uncertain outcomes after a transport error; keep the request key and reconcile the actual row and audit before taking further action.

See [Feishu Base developer guide](https://open.feishu.cn/document/agile-project-cycle-management-based-on-bitable/introduction) for platform access prerequisites.
