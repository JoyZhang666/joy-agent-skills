# 在飞书多维表格中建立测试库

准备一个新建的专用空白多维表格（Base）。可保留平台自带的空白表；初始化程序接受至多一张无记录的起始表，再创建八张 CRM 表。关联字段指向目标表中的飞书原生记录。映射文件和协调库请保存在技能目录以外。

1. **准备工具与账号。** 安装 Python 3.10 或以上版本及支持这些子命令的飞书官方 `lark-cli`：`base +table-list`、`+table-create`、`+field-list`、`+field-create`、`+record-list`、`+record-upsert`。用自己的飞书用户配置登录，确认对该测试库有读写记录、建表和建字段的权限。适配器以已登录用户身份调用 CLI，不保存访问令牌。
2. **建表并核对映射。** 将 `CRM_FEISHU_BASE_ID` 设为目标测试库标识，核对无误后建一个私有状态目录。运行 `python feishu.py init --mapping MAPPING`，将 `MAPPING` 换成该目录中的文件路径。同一时间只运行一个初始化进程。保存生成的表标识与结构摘要。用同一映射重跑时，程序会核对字段类型和原生关联目标。如果创建表后丢失回执，先检查尚未登记到映射里的表，再决定是否续办。初始化程序不会删除或替换既有表。
3. **连接协调器。** 运行 `python crm.py --db DATABASE init --feishu-config MAPPING`，将 `DATABASE` 和 `MAPPING` 换成实际路径。此后各次调用使用同一测试库标识、已获授权的 CLI 环境和协调库。按[安装说明](README.md)为每个 Agent 分别登记身份。CRM 审计可区分经办 Agent；共用飞书登录账号时，它们共享该账号的平台权限。
4. **用虚构业务验证。** 先建组织和阶段，再建一条同时关联两者的商机。更新前查版本和哈希，更新后回读业务与审计。启用业务用途前，分别验证旧版本更新、重复请求和中断恢复。协调器 SQLite 文件放在一台主机的本地磁盘。多台电脑各自建立协调库再写同一个 Base，无法统一安排写入顺序。

飞书字段名沿用数据模型中的标识。数值和日期使用原生字段；单选及多值关联使用原生关联字段，由 CRM 校验允许的关联数量。请保留受管字段名，协调写入期间避免同步人工修改。在表不可读或分页查询失败时，按错误处理；远端写入遇连接中断时，保留原请求键，先核对实际业务与审计，再决定下一步。[飞书多维表格开发指南](https://open.feishu.cn/document/agile-project-cycle-management-based-on-bitable/introduction)
