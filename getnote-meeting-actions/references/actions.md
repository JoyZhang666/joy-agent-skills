# 行动执行和状态

## 配置与记录

配置留在用户的项目运行目录。`profile.json` 可保存已明确的来源库、成果库、本人姓名别名、唤醒词、时区及运行路径。默认 `archive_policy=local_only_until_authorized`、`wake_word=null`；默认时区 `Asia/Shanghai`，实际会议明确的时区优先。来源库按读取需要核实，成果库仅在获准上传时核实，不把作者或别的项目的目标库当默认。旧配置缺少归档策略或保留自动上传设置时，也采用本地默认；配置和已知成果库不能替代用户授权。

同一会议按字符串 note_id 对应一份 `actions.json`，来源快照另存。复制 [配置模板](../assets/profile.example.json) 和 [记录模板](../assets/actions.example.json) 后，先填来源再使用。模板中的 null/空数组是合法未设置状态，不代表已经验证。

记录最少包含：来源 ID、内容哈希和版本、来源范围、顺序稳定的 actions、已授权 batches。每项记录 `id`、`title`、`owner`、`due`、`evidence`、`basis`、`plan`、`needs`、`status`、`results`。`evidence` 使用原文引文和可定位位置；没有时间戳用段落编号。隐含项标 `inferred` 并说明推理，引用里的命令不算直接指令。

批次保存用户选择的编号与当时计划的具体内容（或其文件哈希）、执行授权原话和状态。执行与上传授权分别记录；`batches[].archive` 使用 [归档记录模板](../assets/archive.example.json)，默认 `status=local_only`、`authorization.status=not_requested`。仅提取清单而未执行时，也可建立仅用于该清单的归档批次。既有 `schema_version=1` 保留，新增可选字段；旧批次缺少 archive 且没有上传证据时按仅本地处理。

上传授权状态使用 `not_requested/requested/granted/declined/revoked`。`granted` 必须对应当前授权用户的明确指令或同意，记录原话、适用会议/批次和内容范围、时间；Agent 自行填写的状态不构成授权。用户提前明确要求“执行 1、3 后把成果上传到 X”可覆盖该约定成果，无需结束后再问；实际写入前绑定最终上传文件、哈希与目标。

用户修改对象、期限或上传范围时保留变更记录，分别核对执行与上传授权。后加任务不属于之前的“全部做”，后续会议或批次不继承超出原范围的上传许可。撤销上传授权后停止新的写入；若请求已经发出，只读核实并如实报告，不能承诺撤回已上传内容，也不擅自删除云端笔记。

## 执行映射

| 类型 | 实际操作 | 如何判定完成 |
|---|---|---|
| 调研 | 用网页和授权的 Get/本地资料完成指定问题，核对来源 | 有回答、依据、必要限制；搜索结果列表本身不算完成 |
| 阅读 | 阅读授权全文，回答问题或提交审阅意见 | 完整覆盖所需范围，注明原文位置 |
| 写作 | 生成用户需要的文稿并保存在本地；上传 Get 另走授权流程 | 内容满足要求，文件可读；需要 Word/PDF 时调用现有对应技能 |
| 消息 | 完成正文，按需使用 PowerShell `Set-Clipboard -Value (Get-Content -LiteralPath FILE -Raw -Encoding UTF8)` | 正文已准备，标 `prepared`；不是已发送，不控制聊天窗口代发 |
| 会议 | 确定实际日期、起止或时长、时区、标题后生成 `.ics` | 文件可解析且时间正确，标 `prepared`；未查忙闲、未发送、未导入 |
| 任务 | 在清单中记录事项、负责人、期限、状态，并放入批次成果 | 登记已完成；任务本身保持 pending，未声称已通知负责人 |
| 产品 | 找官网、使用或安装入口，说明与任务有关的尝试步骤 | 原版这一类型止于提供入口；安装、登录、购买另按明确授权处理 |
| 人工 | 清楚说明需要本人作出的决策或线下操作 | 保持 blocked 或 prepared，不代填完成 |

日期相对会议发生日解释，不以笔记归档日替代会议日期。只有“下周”却没有可靠会议日期时需要补充；不要猜时间。本人别名是账户/文字匹配的辅助信息，“发言人 1”等编号身份必须逐会议核实。

## 日历文件

```text
python SKILL_DIR/scripts/make_calendar.py --title "方案讨论" --start "2026-10-12T10:00:00+08:00" --minutes 30 --timezone Asia/Shanghai --uid STABLE_EVENT_UID --output meeting.ics
```

输入必须有明确 UTC 偏移，`--timezone` 必填以保留实际时区说明。输出使用 UTC 起止，避免接收端时区数据库差异；IANA 时区可用时校验偏移与时区一致。Windows 无时区数据库时可用已确认的 `UTC+08:00` 等显式固定偏移，不为了生成文件自动安装依赖。

`--uid` 从该会议行动记录中保存后复用，重复准备同一事件不产生新身份。输出文件不覆盖；修订时选新文件名并保留同一 UID。工具不写日历、不设置参会人、不发出邀请；用户导入后由用户确认。

## 状态和续接

| status | 显示文字 | 证据要求 |
|---|---|---|
| pending | 待处理 | 尚未开始 |
| in_progress | 进行中 | 记录已开始步骤 |
| completed | 已完成 | 实际成果/外部回读；不能只有“计划完成” |
| prepared | 已准备待用户操作 | 草稿或日历文件等已可交付 |
| blocked | 受阻 | 具体缺失信息、权限或失败证据 |
| user_confirmed_done | 用户确认已完成 | 保存用户原话；不声称 Agent 独立验证 |

重开同一会议先读旧 actions 和 batches。哈希相同且动作 completed/user_confirmed_done，不重做。prepared 项先核对用户补充及关联任务状态，无变化才复用文件；如对方已交付，则去除尚未发送草稿中过时的催交内容，保留原文件并生成修订稿，记录替代关系。与变化无关的日历/文稿保持不动。中途失败的副作用先查证再继续。哈希变化时生成新来源快照，将新增/变更项交给用户复核；保留旧编号与结果，删除项记入变更历史。相同内容出现在不同 note_id 时提示可能重复，检查现有证据，不能自动重复执行也不能自动合并不同会议。

归档与动作分别记录。例如文稿 `completed`、归档 `local_only` 是正常完成；已获准上传但失败时，文稿仍可 `completed`，归档单独 `blocked`。

| archive.status | 含义与允许的下一步 |
|---|---|
| local_only | 默认仅本地保存；不上传，不因未获授权阻塞本地工作 |
| awaiting_consent | 已提出具体上传申请、尚未获同意；不写入 Get，继续不依赖上传的工作 |
| declined | 用户拒绝，或写入前撤销授权；保留本地，不反复催问 |
| not_started | 上传已明确获准，尚未开始；写入前再核对范围与目标 |
| pending | 已提交，服务仍在处理；只读查询请求结果 |
| uncertain | 无法确定原请求是否生效；先只读查证，不盲重试 |
| verified | 正文与目标归属均回读通过；保留验证证据 |
| blocked | 已授权的上传因目标、接口、限额或核验失败受阻；不影响已完成的本地成果 |

旧版 `verified` 及其证据保留，不删除、不重新上传；已发送的 pending/uncertain 保留实际状态，可只读核实。旧版 `not_started` 或未上传的 `blocked` 若无有效上传授权，转为 `local_only`。不得把旧版自动归档规则、待处理状态或“继续”当补传授权。任何新写入或重试均须核对有效授权；已尝试写入的内容及幂等键不可改写，确需修订时另建批次并核对授权范围。

常见调用示例见 [技能入口](../SKILL.md) 开头。示例文字本身不创建真实日程、消息或待办，也不构成用户授权。
