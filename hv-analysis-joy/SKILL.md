# hv-analysis-joy｜横纵研究与商业尽调

Joy 改编版；适用于 Codex，当前验证环境为 Windows。

输入研究对象、用途和可用材料，交付有证据定位的分析、主要缺口与下一步。基于上游横纵分析框架改编，来源见 [署名与许可](THIRD-PARTY-NOTICES.md)。

## 开始与选择深度

确认对象、决策问题、地域、资料截止日和交付形式；已有答案直接使用。存在会改变研究方向的简称、同名、母子公司或人物角色歧义时，先核实，再请用户选择无法由证据排除的候选。

- **快速筛选**：回答是否值得进一步了解；一页简报、关键证据、材料缺口。
- **标准研究**：纵轴、横轴、交汇洞察，加一页结论；范围随问题调整。
- **深度尽调**：增加主体/客户/产品能力核验、反证和访谈问题；涉及财务或客户声明时不以宣传替代审计材料。
- 用户只要单轴或人物研究时，保留相应证据和 QA，省去不相关部分。不要强制六个研究子问题、固定字数或来源数量。

研究方法和对象适配见 [研究与尽调](references/research-method.md)。从一个能影响决定的问题开始，不因流程复杂而增加无关研究。

## 研究与证据

1. 优先读取用户选定且获授权的材料，再查当前官方公开来源。为实体、时间、财年、币种、业务范围和客户关系建立一致口径。
2. **纵轴**：起源、里程碑、阶段、关键选择及路径依赖。区分事件已发生与对动机的解释。
3. **横轴**：选择可比对象。集团与事业部、不同供应链层级、不同地域/期间的数据分列，不能直接排名。直接客户、间接配套与自述客户分开。
4. **交汇**：写清支持证据、替代解释、反面证据与可验证信号。未来情景列触发条件，不给无依据的概率。
5. 按 [证据格式](references/evidence-format.md) 留存关键事实。来源缺失、冲突、自述和估算显式标注；转载多个页面不等于多个独立来源。网络失败时只使用已保存且可定位的证据，保留缺口。

合作吸引力与证据充分度分开呈现；不把模型自报置信度、来源数量或案例中的分数当成通用统计公式。商业信息不可见时，先提出核验问题；只有研究需要且存在合理依据时才做估算，并展示依据、区间和局限。

## 交付和继续

- 默认保存到用户指定的本地工作目录；使用 [交付模板](assets/report-template.md) 和 [决策简报模板](assets/decision-brief-template.md)。各次运行使用新目录，保留原始证据、初稿、QA 和修订版。
- 聚合已有 SQ JSON 时使用 `scripts/aggregate.py --input-dir <原始目录> --output-dir <新目录> --expected-sq <实际计划ID...>`。脚本检查结构与计划覆盖，**不会验证事实**。返回码 2 表示仍有计划中的 SQ 缺失。
- 需要 PDF 时先读 [安装与工具](references/setup.md)，使用 `scripts/md_to_pdf.py`。只接受受限 Markdown 和明确列出的本地 PNG/JPEG/WebP 素材；脚本禁用页面脚本、拦截网络并使用离线浏览器上下文。完整视觉检查和真实资料验收另行完成。
- 飞书等在线交付按当前任务明确授权及实际可用工具执行；本包不包含账号、收件目标或自动发送脚本。先交付可审阅本地文件，外部操作不因安装 Skill 自动获准。
- 当前环境允许且任务可独立拆分时可并行研究；否则主 Agent 分批完成。给协作者明确对象、口径、资料边界和保存位置，回收后检查实际文件。出错只补缺失部分，不凭摘要或记忆重造证据。
- 用户要求更新时，对已保存事实重新查证，记录新旧差异及受影响结论；不默认创建后台监控。

完成条件：研究问题得到范围明确的回答，主要结论有可定位来源或假设标记，表格口径一致，缺口与下一步清楚，实际文件可读。文件生成、技术检查、事实 QA 和业务验收分别说明。
