# 批量命名整理

先调查、再展示完整方案，用户确认具体清单后才改名。适用于中文课程、音频、视频、图片和一般资料；文件内容、扩展名和逻辑目录层级保持不变。执行工具首版面向 Windows，使用 Python 3.10+ 标准库。

## 工作流程

1. **界定范围。** 报告绝对目标路径、是否递归、是否改目录名及目标根目录本身。默认仅直属文件；不要为命名任务播放媒体、转写音频或生成 README。
2. **全量调查。** 枚举全部范围内项目，包括隐藏项，核对大小、SHA-256、编号、重复内容、命名模式、广告候选和疑似乱码。目录改名必须覆盖其所有后代的完整性，即使不改后代自身名称。执行 `audit`，将证据放在源目录外。
3. **提出方案。** 先读 [清理规则](references/naming-policy.md)，给出具体规则、删改理由、前后示例、长度变化、冲突与未决项。有实质取舍时提供方案比较。名称本来合理时报告“已检查，无需改名”。
4. **冻结审批清单。** 用 `plan` 生成 `plan.json`、`rename-manifest.csv` 和 `preview.md`，涵盖全部项目及不改名项目。JSON 是执行依据，CSV 为逐行对应的可读映射，危险文本有 `[text] ` 安全显示标记。展示清单链接、计划摘要、范围及异常；用户确认后记录该摘要。规则、清单或范围变化后重新提交。
5. **执行获批计划。** 读 [执行与恢复](references/execution.md)。先用用户实际批准的摘要试运行 `apply`，检查全量漂移与冲突，再加 `--execute`。摘要参数是技术绑定，不代表用户已授权；不能自行把生成摘要当作批准。
6. **验收交接。** 核对全部新名称、文件和目录数量、字节数、文件哈希、编号/标题保护及后代路径；验证回滚预览。交付清单、结果与恢复入口的可点击链接并确认存在。阶段状态只能是通过、有证据的跳过、待审批或明确失败。

## 不可省略的约束

- 不删除源文件，不覆盖目标，不主动修改文件内容或文件修改时间，不跨逻辑父目录移动或合并目录。完全重复内容也保留。验证覆盖文件内容、大小、文件修改时间与路径集合，不承诺目录时间、访问时间、ACL 等全部元数据不变。
- 原序号、正文标题、上下集、版本、扩展名默认保护。标题内广告可以清理，但每处修改必须有明确边界、理由与获批差异记录。
- 乱码不是“不认识的字符”。先排除终端显示问题，优先提出有依据的恢复；不按“只保留中英文数字”过滤名称。
- 不以全文正则删除所有括号、所有长数字、所有网址样式字符串或所有“QQ/微信”。检测只是候选，不是执行授权。
- 原编号缺失不补造；不把重复编号等同于重复内容。若只去广告，不重新编号或换分隔符。
- 不为凑长度截断核心标题。主体超过文件 60 字符、目录 40 字符仅提醒；大小写、Unicode 归一化、结构标签精简须在方案中说明。
- 源文件集、哈希、文件修改时间或范围漂移时拒绝执行。先重新调查和提交新清单，不强行沿用旧计划。
- 首版拒绝链接/目录联接、目录合并、大小写专用改名、循环交换、现存目标冲突及最终路径达到 240 UTF-16 单位的计划；不自动修改系统长路径设置。
- 执行失败尝试从持久日志恢复；发生外部冲突、内容变化或日志损坏时保留现场，明确报告“恢复未完成”。不能宣称多项改名具备文件系统级原子事务。

## 工具和质量检查

运行 `scripts/batch_names.py --help`。无需下载依赖；Windows 命令使用 `python -X utf8 -B` 或已核实的本地 Python 路径。

每阶段的 100% 指所有范围内项目/映射均已计数和验证，不表示已完整阅读或播放文件内容。四个关口分别检查：调查覆盖、审批映射、执行结果、最终交付。通过后不无故重复全套检查。

结构验证使用 Skill Creator 的 `quick_validate.py`；执行行为使用 `tests/test_batch_names.py`。新增规则先在匿名或隔离样例试运行并验证恢复，再展示真实映射。真实名称样本和源数据不得打包进通用技能。

设计来源及取舍见 [实践依据](references/practices.md)。技能对已合理命名目录可仅审计；内容概述和知识库 README 按用户需求交给 `knowledge-folder-curation`，不自动创建。
