# 一个 Skill 公开前，如何检查隐私与来源？

把自己使用的工具分享出去，不能只改一下姓名。真实信息还可能藏在示例、脚本默认值、日志、截图、压缩包和提交历史中。

我的发布检查分成几层：

1. **明确公开范围。**在独立副本中整理待发布文件，运行数据和私有配置留在外面。
2. **检查正文与附件。**寻找真实身份、私人路径、账号、内部地址、密钥及客户资料；示例换成明确标注的虚构内容。
3. **检查行为。**了解脚本是否上传、删除、覆盖、计费，说明权限和确认时机。
4. **检查来源。**保留上游项目链接、改编说明、原版权与许可；不能只写一句“感谢”替代许可要求。
5. **检查历史和远端。**ZIP 通常不包含 Git 历史；另外核对提交作者、隐私邮箱、旧版本和最终上传内容。

**虚构例子：**示例中的本机用户名已经换掉，但日志里仍有真实 API Key。这份包仍然不能公开；如果真实密钥曾泄露，还需要在服务商处撤销或轮换。

这是持续检查的方法，不是“绝对无风险”的认证。公开内容只保留帮助别人理解和使用工具所必需的信息。
