# 返回了文字，为什么还不能算“全文交付”？

一份很长的转写稿，也可能漏了开头、重复中间，或在结束前中断。文字数量只能说明“有结果”，不能证明“覆盖了全部来源”。

在 Youtube 转写全文稿里，我把交付目标与验收状态分开：输出是 Markdown 全文稿草稿，仍然需要核对。中断、告警或缓存不能自动升级为完整成果。

一个可执行的核对顺序是：

1. 确认稿件保留来源和所用处理路线。
2. 查看是否出现窗口缺失、中断或待复核提示。
3. 对照开头、结尾和中间若干位置，检查内容是否对应；抽查通过也不能保证逐字无误。
4. 需要高准确度时继续逐段核验，发现不确定内容就保留待确认标识。

**虚构例子：**教学视频共三个部分，稿件只包含前两部分。即使正文流畅，也应记录“缺少第三部分”，不能把它当作全文交付。

这个判断也适用于其他 Agent 任务：说明成果覆盖了什么、还有什么没验证，比一句“已完成”更有用。
